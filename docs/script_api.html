2 快速上手

脚本是 UTF-8 文本文件,写完放到约定目录就生效,不需要编译、不需要注册。

2.1 脚本放在哪里

位置是什么清单
exe目录\packages\<id>\随包发布的脚本包(只读)package.toml
%LOCALAPPDATA%\DogEdit\packages\<id>\用户安装的脚本包package.toml
工作目录\packages\<id>\开发中的脚本包(优先级最高,"正在改的那份赢")package.toml
exe目录\scripts\*.lua、工作目录\scripts\*.lua散装脚本:免清单,包名 = 文件名无
同名规则同一个包 id 在多个根目录出现时,后面的根覆盖前面的(开发目录 > 用户目录 > 随包目录);被覆盖的那份在「脚本包」对话框里不单列。散装脚本的归属包名是空串。

2.2 第一个脚本

在 exe目录\scripts\(或工作目录的 scripts\)放一个 hello.lua:

-- 三个最基础的出口:弹窗、日志、版本号
App.alert(("hello from %s (%s), doc %q has %d lines"):format(
    App.version(), _VERSION, App.doc.name(), App.doc.line_count()))
App.log("hello.lua finished")

启动 DogEdit 即装载。App.alert 弹一个消息框(标题 DogEdit Lua);App.log 与 print 落到 stderr(行前缀 [lua] )和调试输出(OutputDebugString,调试器里可见)。GUI 程序的 stdout 是空的,print 不会打印到任何控制台 —— 想看日志要么从终端启动,要么挂调试器。

改一下 hello.lua 再保存:装载过的每个脚本文件都被一个 700 ms 的定时器盯着,指纹(修改时间 + 长度)一变就自动重跑,不用重启。语法错的版本不会顶掉正在工作的版本 —— 屏幕保持上一次成功的样子,错误打一行日志。

2.3 运行现成脚本的入口

  • App.command 注册的命令出现在「扩展」菜单底部,形如 Lua: 命令名(见第 7 章);写了 launch 的按需包例外,它们只有一行菜单,内部命令不上菜单。
  • 脚本包默认随启动自动装载;「工具 → 设置 → 脚本包…」里可停用 / 启用(见第 15 章)。写了 launch 的按需包开机不跑,点「扩展」菜单那一行才启动(见 15.2)。

2.4 第二个脚本:读文档、改文档

示例脚本「去除行尾空白」全文如下 —— 它演示了遍历行、读行文本、按列区间替换这一整套核心 API:

local n = 0
for i = 1, App.doc.line_count() do
    local t = App.doc.line(i)
    local keep = t:match("^(.*%S)") or ""
    if #keep < #t then
        -- 列区间是 [start, end):末端用 #t+1 表示"行尾之后"。
        App.doc.replace(i, #keep + 1, i, #t + 1, "")
        n = n + 1
    end
end
if n > 0 then
    App.log(("trim_trailing.lua: %d lines trimmed"):format(n))
end
return n

列坐标是 UTF-8 字节列(见第 4 章),# 和 string.sub 与它正好对齐,含中文的行也正确。脚本对文档的修改走与键盘输入相同的撤销通道。

3 运行模型

一个进程一个常驻 Lua 状态:脚本装载一次,注册(命令、事件、快捷键、画法、定时器)存活整个生命周期。

3.1 两个执行档

每个回调都在下面两种档位之一里跑,差别是「能碰到什么」:

档位什么时候能用的 API不能
意图档(有 bridge)事件、命令、定时器、点击、快捷键、启动装载全部:App.doc.*、App.sel.*、App.run、App.alert、App.taskbar…—
绘制档(无 bridge)接管绘制的回调、状态栏 update画布 c、上下文 ctx、App.now()、App.log/print、ctx.theme碰不到文档(App.doc.* 一律报错)、跑不了命令、改不了状态、碰不到任务栏 —— 想做事就返回值
为什么这样设计绘制跑在 WM_PAINT 里,那时编辑器状态正被借用;重入轻则改坏文档,重则进程崩溃。绘制档不是「靠约定别乱来」,而是根本没给工具。绘制回调必须是纯函数:同样的输入画出同样的东西 —— 这也是绘制缓存的前提。

3.2 队列:回调里不直接执行的动作

回调执行期间编辑器状态被借走,所以三件事在回调里只入队,回调返回后由宿主统一派发:

调用入队的事派发时机
App.run(命令名)跑一个命令(脚本命令优先,没有就落内置命令表)本回调返回之后、bridge 还在的那个缝隙;每轮最多派发 256 件,超限整队丢弃并记日志
App.defer(函数)一个普通函数
App.view.scroll_to(line, col)滚动视口

嵌套调用自然接到队尾:命令 A 里再 App.run("b"),b 会在 A 返回后跑。App.pending() 返回还排着几件,给脚本自己诊断用。

3.3 预算与限额

约束值超了会怎样
Lua 堆内存64 MB抛 not enough memory,按普通错误处理
绘制回调 / 状态栏 update 指令数20 万条抛 script exceeded its instruction budget (N instructions);绘制回调报错 → 交回内置画法,其余 → 记日志
事件 / 命令 / 定时器 / 装载 指令数2000 万条
同时存活的定时器64 个登记被拒:too many timers (max 64)
一轮定时器派发最多 64 发多出来的留到下一跳
待办队列256 件入队超限静默丢弃计数;派发超限整队丢掉
为什么按指令数掐沙箱挡得住 io/os,挡不住 while true do end。指令数是确定的:同一段脚本每次烧掉的格数一样,报错信息里带预算值,好对照。

3.4 装载、重载与注册归属

  • 启动顺序:建宿主 → 设存储目录 → 按「依赖拓扑 → order → id」跑每个包的每个脚本(单文件失败不带走整包) → 最后跑散装脚本。装载失败汇总成一个弹窗(最多列 5 条,其余见日志)。
  • 热重载按文件指纹触发;重跑前先编译再清旧注册 —— 语法错的版本清不掉正在工作的那套。
  • 同一文件重跑会整块替换它登记的所有东西(事件、命令、快捷键、画法、定时器、窗格声明…),不会越跑越多。
  • 每条注册都记着「来自哪个文件的哪一块」,「脚本包」对话框停用一个包、或关掉按需包的窗格时,能把这些一次清干净,并跑满两轮 Lua GC 把闭包和表真的还回去。
  • 窗格声明是活的:增删窗格当场建/拆 HWND,不用重开进程。声明每条都带块名,所以能反查「这块窗格是哪个包的最后一块」—— 按需包据此在关窗时整包退出。

4 坐标约定

文档 API 用 1 基行号 + 1 基 UTF-8 字节列;视口 API 用 0 基行号 + 0 基字符列。两把尺子,别混。

4.1 文档 API 的坐标

  • 行号从 1 起,App.doc.line_count() 是最后一行;越界返回 nil / false。
  • 列是该行 UTF-8 文本里的 1 基字节偏移:1 是行首第一个字节;len+1 是行尾之后(App.doc.line_len(n) 返回不含换行符的字节数)。
  • Lua 字符串是字节串,#、string.sub、string.byte 的下标与这套列坐标天然对齐。
  • 区间一律 [start, end):含起点,不含终点。删除整行文字是 replace(l, 1, l, len+1, "")。
输入换算规则
字节列落在多字节字符内部向下取整到该字符的起始字节
字节列超过行尾夹到行尾(插入时等于"接到行末")
span_text/replace 的两个端点次序颠倒自动交换,按小→大处理
行号 0 或超出 line_count()(读 API)nil
行号越界(写 API)false;只读文档也返回 false
-- 行 "中文abc":字节列 1='中'(占 3 字节),4='文',7='a',10=len+1(行尾之后)
App.doc.insert(1, 7, "X")     -- 中文Xabc
App.doc.line_len(1)            -- 10(不含换行符)

4.2 视口 API 的坐标

App.view.info() 与 App.view.scroll_to() 服务于「现在看到哪儿」这类几何问题:

字段含义基
top_line / scroll_to 的 line视口顶部可见的逻辑行0 基
top_col / scroll_to 的 col水平滚动位置0 基字符列
rows / cols可见行数 / 列数(按当前字体与换行模式)—
caret_line / caret_col光标位置0 基行、0 基字符列

同理,绘制档里 ctx.rows[i].line 也是 0 基逻辑行号。1 基与 0 基的分界:「改文档」一律 1 基字节列,「看几何」一律 0 基字符列。

5 App 核心 API

全局只有一张表 App(以及被改写的 print)。本章是不碰文档的那一半。

App.log(msg)—日志一行:stderr([lua] 前缀)+ OutputDebugString。绘制回调里也能用(那时它走日志 sink)

App.on(事件名, fn)—注册事件回调(见第 7 章)

其余成员在后续章节:App.doc(第 6 章)、App.sel / App.view(第 6 章)、App.theme(第 14 章)、App.ui(第 9–14 章)。

可用的标准库沙箱只装了 coroutine、table、string、math、utf8 五个标准库。没有 os、io、package、debug:读文件、写文件、环境变量、时间格式化都不存在 —— 脚本能碰到的全部 I/O 就是本文档列的这些。往全局写变量只影响脚本自己(读会穿透到标准库,写不会污染)。

5.1 任务栏进度状态

外部工具跑完时,任务栏按钮会亮起一条满格进度状态:退出码 0 用 normal(系统强调色),非 0 或被终结用 error(红色),同时还有一枚绿色对勾 / 红色叉号徽标。Windows 11 的任务栏只把进度画成图标下方约 30×4 像素的细线,normal 取系统强调色而不是固定的绿色;完成时这条状态直接满格显示该颜色,不再闪动。窗口在前台时 6 秒后摘除;窗口在后台时提醒一直保留,徽标、进度条和闪烁都要等用户点击任务栏激活窗口才由宿主一起摘除(倒计时期间切走也一样保留)。「选项 → 常规」可以单独关掉这一项。App.taskbar 驱动的是同一块状态,脚本因此能给自己发起的任务报进度、报结果。

state按钮上的样子
"none" / "off"没有进度条(收尾用)
"indeterminate" / "busy"滚动跑马灯,总量未知时用,忽略刻度
"normal" / "ok"系统强调色(Win7/10 上是绿色),按 completed/total 填充
"error" / "fail"红色,按 completed/total 填充
"paused" / "pause"黄色,按 completed/total 填充
-- 自己跑的任务:跑马灯 → 报刻度 → 结果 → 6 秒后收尾
App.command("build.status", function()
    App.taskbar("indeterminate")
    App.taskbar("normal", 3, 10)
    local ok = true                        -- 换成你的任务结果
    App.taskbar(ok and "normal" or "error")   -- 满格系统色 / 满格红
    App.timer(6000, function() App.taskbar("none") end)
end)
谁负责摘除宿主只摘自己挂上去的那一条:脚本一调 App.taskbar,进度条就归脚本所有,仍在倒计时的工具完成提醒不会把它清掉;反过来,工具完成时若脚本正挂着进度条,提醒结束后会把脚本那条原样还回去。宿主不替脚本自动清除,所以长任务记得用 "none" 或定时器收尾。这是意图档 API —— 绘制回调里没有 bridge,调它会抛 no bridge: called outside a host entry point。

6 文档、选择与视口

这组 API 只作用于当前活动文档(页签栏上正在编辑的那一个)。批量处理多文档需要把命令挂到事件或由用户逐个执行。

6.2 App.doc — 写

调用返回说明

  • 写完不需要刷新 —— 宿主在回调返回后统一收尾(夹光标、重排版、重画)。

7 事件、命令与快捷键

脚本进入程序的三个正式通道:事件回调(被动)、命令(菜单可点)、快捷键(键盘可达)。

7.1 事件:App.on

App.on("doc.saved", function()
    App.log("saved: " .. App.doc.name())
end)
事件名触发时机状态
doc.saved当前文档保存成功之后(含另存)已触发
doc.opened文档打开之后已触发
doc.closed / theme.changed / caret.moved / view.scrolled—可注册、当前版本无触发点登记合法但外壳尚未接线,回调不会执行
  • 同一事件可以多个脚本各挂一个回调,按装载顺序依次执行;某个回调报错只记日志,不影响后面的。
  • 事件名大小写敏感,但大驼峰旧名仍认 (DocSaved、DocOpened):触发时新旧名字两边都会跑,改名不会让老脚本静默失效。
  • 回调是意图档:能用全部 API,包括 App.run(排队,回调返回后真正执行)。

7.2 命令:注册与运行

App.command("acme.tick", function()
    App.alert("ticked at " .. App.now())
end)
App.keymap("Ctrl+F9", "acme.tick")

-- 别处(或别的脚本)触发它:
App.run("acme.tick")
  • 注册的命令按名字排序出现在「扩展」菜单底部,形如 Lua: acme.tick。
  • App.run(名字) 的解析顺序:脚本命令优先,没有同名脚本命令就落到内置命令表。内置命令认两种拼法:点分("file.save")或带前缀("cm_file_save")。
  • 命令名长度须 1..128 字符。运行不存在或被拒绝的命令,结果只是一行日志(App.run: no command …),不弹窗。
内置命令名怎么查内置命令是 cm_ + 蛇形名的形式,比如 file.save、edit.copy 风格 —— 完整对照表见用户手册第 24 章(快捷键)与「命令行」一章;key.ini 的 [Shortcut] 段用的也是同一套名字。写错时 App.run 的日志会点名。

7.3 快捷键:App.keymap

App.keymap("Ctrl+Shift+T", "acme.tick")   -- 绑到自己的命令
App.keymap("Ctrl+Alt+D",   "file.save")   -- 也能绑内置命令(点分名)
  • 组合键写法:修饰词 Ctrl / Shift / Alt(Control 也认)任意组合,加号连接,最后是一个键:字母、数字、F1..F12,或下列具名键(大小写不敏感):Up / Down / Left / Right / Space / Enter / Esc / Tab / Backspace / Insert / Delete / Home / End / PageUp / PageDown。别名 Return / Escape / Back / Ins / Del / PgUp / PgDn 同样认。不支持双键和弦,也不支持其它键名;写错当场报错并列出合法格式。
  • 派发优先级是最后:内置命令表(key.ini 与内置键)先查,和弦前缀第二,都未命中才轮到脚本 —— 脚本不能覆盖内置键。
  • 焦点规则:编辑区里要求带 Ctrl 或 Alt(裸字母、Shift+字母要落进文档);在脚本自建窗格内无此限制(窗格获得焦点时裸键也派发)。
  • 热重载同文件会整块替换该文件登记的快捷键。

7.4 状态栏与工具栏上的命令

  • 状态栏段声明 click = "命令名"(见 12.2):点击该格跑命令,脚本命令与内置命令都认。
  • 工具栏按钮声明 command = "命令名"(见 12.3):同样先查脚本命令再落内置。

8 持久存储 App.storage

字符串到字符串的键值表,存盘持久,重启还在。脚本保存设置、计数器、窗口状态的正规去处。

end
调用返回说明

t:get(key)字符串或 nil没有该键得 nil

10.3 回调契约

ui.paint:on("tab", function(c, ctx)
  ...                                  -- 往 c 上发指令,读 ctx 拿几何与状态
  return true                          -- 返回值决定谁画
end)
返回含义
true这一块完全由脚本负责,内置画法让位
false / nil交回内置画法(已发出的指令不会被用)。只想改某一格时,先画那格再 return false 也不行 —— 要么全接要么全让
数字(脚本窗格)数字按真值处理(等于「我画了」),同时兼职报内容总高(DIP):宿主拿它算窗格滚动条的滑块长度与最大滚动量。写 return 1200 就多告诉宿主一件事,老皮肤 return true 一字不改
抛错记一行日志(每处只报一次,不去重的话每秒几百行同样的栈),交回内置画法 —— 一个坏皮肤不该让窗口白屏

10.4 绘制缓存与「纯函数」规矩

  • 结果按「区域 + 部件 + 状态 + 尺寸 + DPI」缓存;命中时不进 Lua,直接还上一份指令。正常皮肤的命中率在 90% 以上。
  • 缓存键放不下的输入(格子文字、滑块位置、文档快照、滚动量……)按「回调读过才比对」处理:没读 ctx.text 的画法,文字换了也照样命中。所以推荐用 c:text(r, "@text", …) 让宿主画字 —— 那种写法天生不读文字,缓存最有效。
  • 回调里读 App.now() 会让这份画法永不进缓存(动画就这样做);闭窗统计里会单列这类次数。
  • 点击回调可能改了画法要用的状态(计数器、选中项),宿主看不见那些变量,所以点击之后该区域的缓存整区丢弃。
  • App.ui.repaint(区域名) 是显式的「这份缓存旧了」:命令 / 事件 / 定时器里改了 Lua 自己的状态后点名那一块,宿主丢缓存并作废对应窗口;不点名则整帧重画。点击回调已经自动丢该区域缓存,不必重复调。不要在绘制回调里调它 —— 画法仍须是纯函数。
  • --skin-debug(或环境变量 DOGEDIT_SKIN_DEBUG=1)让每个绘制回调连跑两遍逐条比对指令,专抓「不纯」的画法;退出时报告副作用处数、缓存命中率、因读时钟不缓存的次数。它让绘制翻倍,平时别开。

15 脚本包

一个包 = 一个目录 + 一份可选的 package.toml。清单只回答五件事:我是谁、要什么版本、依赖谁、按什么顺序跑、什么时候跑。

15.1 package.toml 全解

api = 1                          # 必填;只有 1 被接受
id = "luapaint"                  # 必填,见下方规则
name = "LuaPaint"                # 显示名,可省(缺省用 id)
version = "1.0.0"                # 可省
description = "…"                # 可省
order = 90                       # 同依赖层内的装载顺序,小的先装;可省,缺省 0
requires = ["acme.base >= 1.2"]  # 依赖;可省。只认 >=,别的比较符不收
launch = "贪吃蛇(&S)"        # 可省;写了 = 按需启动,值是「扩展」菜单那一行的文字
scripts = ["paint.lua", "panels.lua"]  # 可省;缺省 = 目录下所有 *.lua 按文件名排序
  • id 规则:小写字母或数字开头,只含 a-z 0-9 . _ -,≤ 64 字符,不能有 .. —— 它会变成目录名、命令前缀、存储目录名。
  • scripts 必须是包目录内的相对路径,不许跳出;写了就按写的顺序跑,哪些文件会跑是个能打印出来的事实。
  • launch 必须是非空字符串。空串、纯空白、布尔、数字一律报错,不静默退回「开机装载」—— 作者以为关掉了自动装载、结果脚本照跑是最难查的一种。值里的 & 是菜单加速键。
  • 清单里写 kind / facets / permissions 会报错而不是忽略:包不分级,什么脚本都能建元素、画画、改文档;真正的约束在回调签名上(画法必须纯、点击回调返回意图)。
  • requires 里的 dogedit 指宿主本身,版本就是程序版本(当前 0.1.0);被依赖包缺了或版本不够,这个包装不上,原因会写进管理器与 --packages 报告。
  • 单个脚本文件失败不带走整包:后面的文件可能正是补它的那个。

15.2 按需启动:点菜单装载,关窗格退出

不写 launch 的包随启动装载。写了 launch 的包是按需启动包,开机一条脚本都不跑:loaded_scripts 里没有它、心跳定时器不会为它 arm、扩展菜单里也只有它自己那一行(不会给包内每条 App.command 各占一行)。

  • 启动:点「扩展 → 菜单文字」(id 段 35500+)。宿主按清单顺序跑这个包的脚本,走和开机装载同一套收尾 —— ui.layout:pane 当场建出真 HWND 并停靠,心跳定时器当场 arm,App.run 排的队当场派发。菜单那行随即变成「关闭 …」。
  • 退出:关掉它带的最后一块脚本窗格(窗格 ✕、双击页签、1284),或者再点一次那行菜单。宿主 purge_package 把十项注册(事件/命令/快捷键/画法/按下/悬停/窗格/状态段/工具栏/定时器)、待办队列、画布缓存一次摘净,跑满两轮 Lua GC,再拆窗格、重算定时器、重建菜单。
  • 包里有好几块窗格时,关一块只收那一块;等最后一块也关了才整包退出。没声明窗格的按需包只能从菜单那行退出。
  • 内部命令不上菜单:按需包里 App.command 注册的命令照样能被 App.keymap / ui.on / App.run 调用,只是不列进「扩展」菜单。小游戏的方向键、暂停、重开不该一人占八行。
  • --ui-doctor 仍会把按需包真跑一遍做语法/装载校验(报告里单列「按需启动」),但它不代表开机装载;--packages 报告也单列一段。
按需包与「停用」是两件事:停用写进 [Scripts] Disabled,菜单里那行直接消失;启用只让那行回来,不会顺手把游戏跑起来。App.ui.style 的运行时外观覆盖是进程级的,按需包退出时不会自动复位 —— 要改外观请在脚本里自己 reset。

15.3 装载顺序与启停

  • 三个根目录(exe 目录 → 用户目录 → 工作目录)全部扫描,同 id 后面的根胜;散装脚本(scripts\*.lua)作为无清单的「包」一起进队列。
  • 排序:先按宿主版本筛,再按 requires 拓扑排,同层内按 order、最后按 id。
  • 停用的包(setting.ini 的 [Scripts] Disabled=)根本不进装载循环 —— 既不排序也不跑。写了 launch 的按需包同样不进循环,只在「扩展」菜单留一行。
  • 按需包被点开之后,它的文件才进 loaded_scripts,此后热重载、心跳定时器、管理器状态列都把它当「在跑」;退出时再从这张表里摘掉。

15.4 管理对话框

「工具 → 设置 → 脚本包…」打开「脚本包」对话框:

  • 带勾选框的表:包 / 版本 / 来源(随包 / 用户 / 开发 / 散装)/ 状态(已启用 / 已停用 / 被同名覆盖 / 装载失败:原因)/ 脚本;底部显示选中包的目录;「全选 / 全不选 / 打开目录 / 确定 / 取消」。
  • 勾选变化当场生效:停用 = 把该包登记的全部东西(画法、事件、命令、快捷键、定时器、窗格、状态段、工具栏按钮)一次清干净,窗格当场拆掉,屏幕立即回到内置画法;启用 = 立刻按依赖顺序重跑。按需包启用只让菜单那一行回来,状态列写「按需启动(点扩展菜单)」或「运行中(按需启动)」。
  • 清单读不出来的包不进表(勾了也跑不了),只在摘要里报个数;细节用 --ui-doctor 查。

15.5 依赖与冲突的排查

装载失败集中在三处能看:启动时那个汇总弹窗(最多 5 条)、日志(逐条带路径与原因)、以及命令行报告(第 16 章)。requires 不满足、id 不合规、api 不是 1、launch 写成空串或布尔、TOML 语法错、scripts 指到不存在的文件,各有各的一句人话。

18.1 保存时自动去行尾空白

App.on("doc.saved", function()
    local n = 0
    for i = 1, App.doc.line_count() do
        local t = App.doc.line(i)
        local keep = t:match("^(.*%S)") or ""
        if #keep < #t then
            App.doc.replace(i, #keep + 1, i, #t + 1, "")
            n = n + 1
        end
    end
    if n > 0 then App.log(("trimmed %d lines after save"):format(n)) end
end)

18.6 一块自己的停靠窗格:秒表

local ui = App.ui
ui.layout:pane{ id = "stopwatch", side = "right", title = "秒表", size = 160, bar = 10 }

local t0 = nil                                    -- nil = 没在计时
ui.paint:on("pane.stopwatch", function(c, ctx)
    c:fill(ctx.rect, "#10161C")
    local elapsed = (t0 and App.now() - t0 or 0) / 1000
    local big = { font = "mono", align = "center", valign = "top" }
    c:text(ctx.rect:inset(8, 12), ("%6.1f s"):format(elapsed), "#E6EDF3", big)
    c:text(ctx.rect:move(0, 60):inset(8, 0), t0 and "计时中… 点击停止" or "点击开始", "#8B949E",
           { align = "center" })
    return true                                    -- 返回 true:整块自己画
end)

App.ui.on("pane.stopwatch", "press", function()
    t0 = t0 and nil or App.now()                   -- 走停切换
    return true
end)

点击回调改了画法要用的状态(t0),宿主会自动丢弃该区域缓存,下一帧重算 —— 不用自己刷新。

18.7 保存后把页签标记点亮一会儿

local until_ms = 0
local lit = false
App.on("doc.saved", function()
    until_ms = App.now() + 1200
    if not lit then
        lit = true
        App.ui.style:set("tab.mark", "#E67E22")    -- 点亮一次就够

    end
end, true)

18.8 给可见行画「超长行」底色(editor.overlay)

local ui = App.ui
ui.paint:on("editor.overlay", function(c, ctx)
    local rows = ctx.rows                          -- 先拿一次,别在循环里读
    local m = ctx.metrics
    if not rows or not m then return false end     -- 没挂行表就交回内置
    for i = 1, #rows do
        local r = rows[i]
        if r.rows > 3 then                         -- 折了 3 段以上的行
            c:fill({ x = m.gutter_x, y = r.y, w = ctx.w - m.gutter_x, h = r.h }, "#2A1E10")
        end
    end
    return true
end)
overlay 回调里别干重活这一档不进缓存,每帧都会跑:别 App.doc.line()(那是意图档 API,这里也调不了),只按 ctx.rows 给的字段画。
