# 接入 LLM 的设计（AI 助手）

> 目标：模型不是旁边再开一个聊天框，而是编辑器里的**另一个编辑者** —— 它知道光标在哪、
> 选中了什么、这个文件是什么语言；它的产出和用户敲键盘的产出走**同一条落地路径**
> （undo 栈、行注记、面板），因此可以被撤销、被拒绝、被脚本复用、被主题画成自家样子。
>
> 现状基线：`Editor::apply_replace` / `apply_edit`（`crates/app/src/app.rs:3728`、`:3754`）
> 是唯一的写入闸门；后台任务一律「std 线程 + crossbeam + `PostMessage`」
> （`win32/lspjob.rs`、`win32/syntaxjob.rs`、`download.rs:367`）。

## 0. 结论摘要

| 决策点 | 选择 | 理由 |
|---|---|---|
| 定位 | 模型的产物走既有三条通道：文本进 undo 栈、判断进行注记、清单进结果列表 | 不新增第二套平行机制，撤销/主题/脚本自动都认得它 |
| 线格式 | 只做两种：OpenAI 兼容 `chat/completions`、Anthropic `messages` | 前者覆盖 OpenAI / DeepSeek / Moonshot / 通义 / Ollama / vLLM / LM Studio；后者覆盖 Claude |
| 传输 | std 线程 + 阻塞 `ureq` + 手解 SSE + `PostMessage(WM_AI)` | 与 `lspjob`/`syntaxjob`/`download` 同一套；**不引入 tokio** |
| 落地 | **草稿层**：一次 undo 步 + 变色 + 复核条 | 缓冲区是唯一有真实排版（换行/折叠/滚动）的地方；原子撤销兜住误改 |
| 多块补丁 | SEARCH/REPLACE 块，**唯一匹配才落** | 整文件重写毁格式；行号 diff 模型算不准 |
| 上下文 | 显式 chips（`@选区`/`@文件`/`@符号`）+ 光标窗口；v1 不做向量索引 | 看得见、改得动、默认最小 |
| 密钥 | DPAPI 加密存 `%APPDATA%\dogedit\ai.dat`；ini 只存引用名 | `setting.ini` 会被同步、被提交、被贴进 issue |
| 默认 | **关**；`--safe-mode` 一律不联网 | 一个开关回到纯本地编辑器，不留后台连接 |
| 面板 | `PaneId::Ai`，走既有停靠体系 | 页签、拖放、关闭、主题全部白拿 |
| 行内补全 | 放 M4，且默认关 | 每次击键都要发请求，是成本与隐私最重的一档 |

## 1. 定位：模型在 dogedit 里是什么

### 1.1 三条既有通道

模型的产出归到底只有两类：**文本**，和**关于文本的判断**（哪几行有问题、哪些文件相关）。
两类各有现成的落点：

| 模型的产出 | 走哪条既有通道 | 现在是谁在用 |
|---|---|---|
| 一段文本（改写、补全、插入） | `Editor::apply_replace` → `UndoStack` | 粘贴、转 Base64、排序、缩进 |
| 对某几行的判断（这行有问题、这里能简化） | `LineTips`（行注记）+ 悬停提示 + 图标槽 | 查找结果、书签、折叠提示 |
| 一批条目（要看的文件、相关符号） | 结果列表 / 大纲视图 | 在文件中查找、ctags/LSP 符号 |

这三条通道都自带三样东西：撤销、主题配色、脚本可读。新功能走老通道，就不需要再为它
写一遍「怎么撤」「深色下什么颜色」「脚本能不能拿到」。

### 1.2 一条硬规矩

**模型只产出两种东西：文本，和关于文本的判断。** 前者必须经过 undo 栈，后者必须落在
既有的注记/结果列表上。不接受第三种产物 —— 「模型自己执行了一个操作」。

唯一看起来像例外的是「把这段交给外部工具跑」：那是**用户**按的键（`toolrun.rs` 那条
通道），模型只是把参数填进去。这条线不越过。

### 1.3 与另外两套扩展机制的分工

|  | Lua 脚本（`dg-script`） | 外部工具（`toolrun.rs`） | AI（本文） |
|---|---|---|---|
| 谁在决定 | 用户写的确定性逻辑 | 用户按的键 + 命令行 | 模型 |
| 输入 | 文档/选区（拷贝） | 选区、文件名、行号 | 文档 + 选区 + 指令 |
| 输出 | 编辑、窗格、菜单 | stdout → 输出窗口 | 文本 / 行注记 |
| 不可预期性 | 无 | 无 | **有**（所以要草稿层） |
| 关系 | AI 是脚本的一个原语（§9） | AI 不重造「跑命令」 | — |

### 1.4 为什么 v1 不做 agent

多步自治（模型自己调工具、自己跑命令、自己改十个文件）不在这一版，理由是信任模型对不上：
现在这个编辑器的每一次写入都对应**用户的一次按键**，而 agent 是「按一次键，模型跑十步」。
要做也是外部工具那一侧的事 —— 那边本来就有进程、有超时、有输出窗口、有「跑之前先问你」。

v1 的 AI 是**单步**的：一次请求，一份产出，用户按一次键决定收不收。这条线守住了，草稿层
才有意义；守不住，撤销栈也救不了「它在我没看的时候改了三个文件」。

## 3. 架构

### 3.1 分层

```
crates/llm  (dg-llm)                     ← 平台无关，可单测，不碰 win32
  profile.rs   档案：端点 / 型号 / 线格式 / 上下文窗口
  wire.rs      两种线格式的请求体与 SSE 增量解析
  transport.rs 阻塞 HTTP + 流式读 + 取消 + 超时 + 错误映射
  message.rs   会话模型（role / parts / usage）
  context.rs   上下文装配与预算截断
  prompt.rs    四个模板（edit / chat / explain / review）
  patch.rs     SEARCH/REPLACE 解析与匹配（唯一匹配才落）
  tokens.rs    粗估（只用来截断，不用来计费）

crates/app/src
  ai.rs            设置读写、DPAPI 密钥、safe-mode 闸门、档案解析
  win32/aijob.rs   工作线程 + WM_AI（照 lspjob 的样子）
  win32/aipane.rs  对话面板（PaneId::Ai）：转录、输入框、chips、流式重画
  win32/aidraft.rs 草稿层：marks、复核条、接受/撤销、一次 undo
  win32/aicmd.rs   命令分发 + 菜单 + 快捷键
```

`dg-llm` 只依赖 `serde`、`serde_json`、`ureq`、`crossbeam-channel` —— 四个都已在
workspace 里，`Cargo.lock` 不新增一棵树。SSE 手解（约 120 行）比引一个 crate 更可控：
它要处理的只有 `data:` 行、空行分隔、`[DONE]` 和两种格式的增量字段。

### 3.2 一次请求的生命周期

```
UI 线程                         工作线程                     端点
  │  Ctrl+K，取选区/光标窗口        │                            │
  │  ── Request{doc, rev, msgs} ─▶ │                            │
  │                               │  POST（stream:true）  ────▶ │
  │                               │  ◀──── data: {...}  ─────── │
  │  ◀── WM_AI（每块一次）──────── │  解析增量，塞通道            │
  │  合并重画（≥30 ms 一次）        │                            │
  │  ◀── WM_AI（Finished）──────── │  ◀──── [DONE]  ──────────── │
  │  核对 doc+rev → 草稿层          │                            │
```

三条规矩：

1. **文档可能换人**。回信带 `doc_id` 与 `rev`（`UndoStack::position()`），UI 线程核对
   不上就丢掉 —— 和 `syntaxjob::Finished.token` 一个道理。
2. **一个文档同时只有一个在飞**。第二次请求先把第一个置取消位，不排队。
3. **取消 = 置位 + 丢 reader**。读循环每块检查取消位；`ureq` 没有中途 abort，靠读超时
   （默认 60 s 无数据）收尾，线程不会永久挂着。

### 3.3 为什么不引 async

现有三处后台任务全是「std 线程 + 阻塞 IO + 通道 + `PostMessage`」，`ureq` 也是阻塞的。
再引一个 tokio 只会得到两套调度、两种取消语义、两份依赖树，而收益是零 —— 一个编辑器
同时最多一两个流式请求，一个线程一个请求绰绰有余。

### 3.4 为什么单独一个 crate

`dg-llm` 不碰 win32，于是 SSE 解析、补丁匹配、预算截断、模板拼装全都能用普通单测守
（`cargo test --workspace` 里跑），不需要开窗、不需要探针。窗口那一层只剩「把字符串
画出来」和「把补丁落到缓冲区」，这两件事本来就有像素验收。

## 4. 配置与凭据

### 4.1 `setting.ini` 的形状

沿用现有 ini 习惯：段名不分大小写，键名区分，空值当没有。

```ini
[AI]
Enabled=1
Profile=deepseek
Context=selection,file
MaxOutput=2048
TimeoutSec=60
Inline=0
InlineSyntax=rs,py,ts

[AI.deepseek]
Style=openai
Endpoint=https://api.deepseek.com/v1/chat/completions
Model=deepseek-chat
ContextWindow=128000
KeyRef=deepseek
KeyEnv=

[AI.local]
Style=openai
Endpoint=http://127.0.0.1:11434/v1/chat/completions
Model=qwen2.5-coder:7b
ContextWindow=32768
KeyRef=
```

| 键 | 含义 |
|---|---|
| `Context` | 允许外发的范围（`selection` / `file` / `cursor` / `symbol` / `tab`），逗号分隔；不在表里的 chip 加不上 |
| `MaxOutput` | 单次回复的 token 上限，也是预算里先扣掉的那部分 |
| `Inline` / `InlineSyntax` | 行内补全总开关与语法白名单 |
| `KeyRef` | DPAPI 里那条的名字；空 = 这个端点不要密钥（本地模型） |
| `KeyEnv` | 非空则优先读这个环境变量，适合 CI 或临时试 |

示例里**没有行内注释**：这个 ini 的读法不剥 `;`，写了就是值的一部分（`settings.rs` 的
`section_in` 只做 `strip_prefix("Key=")` + `trim`）。注释只能单独占一行或干脆不写。

`Style` 只有两个值，这是刻意的：市面上能连的端点，要么说 OpenAI 那套 JSON，要么说
Anthropic 那套。多一个「厂商适配层」只会多一堆没人测的分支。

### 4.2 密钥：DPAPI

- 落盘：`%APPDATA%\dogedit\ai.dat`，`CryptProtectData`（当前用户作用域），
  键名 → 密文的表。
- ini 里只出现 `KeyRef`。**界面从不写明文密钥**；`Key=` 明文仍然**读**（兼容手写配置），
  但保存时一律转成 `KeyRef` + 密文，并提示「已移到加密存储」。
- 换机器解不开是**特性**不是 bug：漫游配置带着走也解不开，密钥不会跟着文件跑。
- `windows` crate 需要加一个 feature：`Win32_Security_Cryptography`。
- 说清楚边界：DPAPI 挡的是「别的用户」和「随手拷走的文件」，挡不住同一用户下的恶意
  进程。文档里要这么写，不要写成「安全存储」。

### 4.3 关掉的三层

| 层 | 行为 |
|---|---|
| `[AI] Enabled=0`（默认） | 菜单项灰掉，面板不开，一个字节都不发 |
| `--safe-mode` | 与上面同，且**不看** `[AI]` 的值 —— 命令行说了算 |
| 会话内「停止」 | 取消在飞的请求，之后不再自动发（行内补全同时停） |

`safety.rs` 加一条 `ai_enabled()`：`!safe_mode::on() && setting 里是 1`。所有出口
（面板、命令、Lua、行内补全）都问这一个函数，不各写各的判断。

## 5. 上下文装配

### 5.1 显式优先

面板顶部是一排 chips，每个 chip 就是一段会外发的内容：

| chip | 内容 | 上限 |
|---|---|---|
| `@选区` | 当前选区原文 + 起止行号 | 选区本身 |
| `@文件` | 当前文件全文（大文件只给窗口） | 800 行 / 32 KB |
| `@光标` | 光标前后各 80 行 | 160 行 |
| `@符号` | 大纲视图里选中的符号体 | 200 行 |
| `@标签` | 另一个已打开文件的窗口 | 同上 |

没有 chip 就没有上下文 —— 这是「默认最小」的落地方式。用户点 `@` 才加，加完能看见
它有多长（chip 上直接写 `@文件 340 行`），也能一键摘掉。

### 5.2 预算与省略

```
预算 = ContextWindow - MaxOutput - 512（安全余量）
```

按 指令 → 选区 → 光标窗口 → 显式文件 → 符号 的顺序装，装不下就整块丢，并在面板底部
写一行「已省略：@文件（超出 12k tokens）」。**不截半块** —— 半个函数比没有更坏。

token 用粗估：`ASCII 字符 / 3.6 + 非 ASCII 字符 × 1.0`，向上取整。它只用来决定丢不丢，
不显示成「计费」。真数字看回信里的 `usage`，面板角上写「1.2k → 340」。

### 5.3 v1 不做向量索引

理由三条：要额外模型（embedding）、要额外磁盘（索引）、要额外失效逻辑（文件改了怎么
办）。而 `dg-core` 已经有全文检索（`filesearch.rs`）、有符号索引（ctags/LSP）、有模糊
匹配（`fuzzy.rs`）。v1 的项目级上下文就做「关键词检索 + 符号表」：从指令里抽词，走
现有的 `run_search`，取前 N 个命中行 ± 3 行。这条路可解释（用户能看见检索了什么），
也可关。

## 6. 输出 → 编辑

### 6.1 两种模式

| 模式 | 用在哪 | 模型输出 | 为什么稳 |
|---|---|---|---|
| 整段替换 | 选区改写（Ctrl+K）、解释后重写 | 纯文本，就是替换后的那段 | 范围是我们给的，不需要解析 |
| SEARCH/REPLACE 块 | 对话里提议改动、跨多处改 | `<<<<<<< SEARCH` … `=======` … `>>>>>>> REPLACE` | 不依赖行号，容忍缩进差异 |

选区改写**不走补丁协议**：范围已知，让模型只吐替换文本，失败面最小。补丁协议只用在
「模型不知道用户会选哪儿」的对话场景。

### 6.2 匹配阶梯（`patch.rs`）

1. 原文精确子串匹配，且**只命中一次** → 取偏移。
2. 归一化：逐行去行尾空白、EOL 统一成文件自己的 → 再匹配。
3. 缩进无关：两边都去掉公共前导空白，按行比较 → 命中后按被匹配块的实际缩进重排。
4. 都不中 → **不落**。报「第 2 块没找到」，并把模型以为的原文前两行显示出来。

「唯一匹配」是硬条件：同一个片段在文件里出现两次，宁可失败也不猜 —— 猜错一次，用户
就得自己找回来。

### 6.3 一次事务

多块补丁必须是一步撤销。现在 `UndoStack::apply` 一次只吃一个 `EditOp`，需要加一个口：

```rust
// core/src/undo.rs —— 已有的 MacroCommand 就是现成的容器
pub fn apply_batch(&mut self, doc: &mut Document, ops: Vec<EditOp>) -> bool
```

`Editor` 那边对应一个 `apply_replacements(&mut self, edits: &[(Pos, Pos, String)])`：
按起始位置**倒序**应用（前面不动后面），书签平移逐条走既有逻辑，最后 LSP 发一次
`didChange`（`to_lsp_changes` 已经能产出多条）。

### 6.4 草稿层：先落字，再复核

三条路里选「先落字」：

| 方案 | 代价 | 问题 |
|---|---|---|
| 另开 diff 窗口 | 小 | 离开上下文判断，用户得来回看 |
| 虚拟文本（在缓冲区里插不存在的行） | **大** | 要再造一套排版/换行/折叠/滚动，和现有 painter 打架 |
| **先落字 + 变色 + 复核条** | 中 | 缓冲区被真的改了 —— 靠原子撤销兜住 |

落地细节：

- 补丁通过 `apply_replacements` 落进缓冲区，**一步 undo**。
- 受影响的行走 `marks`（`(start, end, bg, fg)`，`draw_line` 已经支持）染一层
  `AiDraft` 底色；行号槽挂 `ICON_FLAG`；`LineTips` 写「AI 改动 · 3 行」。
- 复核条是一个 `WS_EX_NOACTIVATE` 弹出窗（照 `complete.rs`），停在第一处改动的下方：
  `[ 接受 ⏎ ] [ 重来 ] [ 撤销 Esc ]  3 处 · deepseek-chat`。
- **用户一动键盘，草稿即落定**：marks 清掉，复核条消失，改动变成普通编辑。理由很实在 ——
  用户接着打字就说明他认了；此时再按 Esc 去撤销一个夹在中间的 undo 步只会撤错东西。
- 撤销：一次 `undo`，因为整批是一步。

### 6.5 不落的三种情况

| 情况 | 行为 |
|---|---|
| 文档在等回信期间被改过（`rev` 对不上） | 不落，面板写「文档已改动，结果作废」 |
| 只读 / 大文件 | 命令灰掉，`apply_edit` 本来也会拒 |
| 补丁有任一块不匹配 | **全不落**（不是「能落的先落」）—— 半套补丁比没有更难收拾 |

## 7. 界面

### 7.1 对话面板（`PaneId::Ai`）

`panels.rs` 的枚举加一格 `Ai => 6`（code 不持久化，不挪别人）。里面是一个真的子窗口，
自己的消息循环、自绘转录：

```
┌ 人工智能 ─────────────────────────────┐
│ [@文件 340 行] [@选区 12 行]  [+]      │  chips 行
├───────────────────────────────────────┤
│ 你  把这段的 unwrap 换成错误传播        │
│                                       │
│ AI  改好了，3 处：                     │  ← 代码块底色用 CallTip 那一对
│     ```rust                           │
│     ...                               │
│     ```                               │
│     1.2k → 340 tokens · 2.4 s         │
├───────────────────────────────────────┤
│ [输入框（多行，Enter 发，Shift+Enter 换行）] │
└───────────────────────────────────────┘
```

- 转录是自绘的：段落按行缓存高度，流式时只重排**最后一条**消息，`InvalidateRect` 合并
  到 30 ms 一次。一个 token 一次重画会把输入线程拖死。
- 数据和别的窗格一样单向：**frame 往面板推**（`set_transcript` / `set_chips`，同
  `outline_win.set_rows`），**面板往 frame 报**（`drain_notifies` 里出「发送」「取消」
  「复制」「插入」）。面板不持有文档引用，要上下文就回 frame 要 —— 它是个独立窗口，
  拿不到 `EditorState` 的借用。
- 输入框是标准 `Edit`（`ES_MULTILINE`）：IME 由系统管，但 `Enter` 的拦截要先问
  `ImmGetContext` 是不是还在组合中，否则中文候选框里的回车会被当成「发送」。
- 渲染只做三样：段落、行内代码、围栏代码块。**不做完整 Markdown** —— 一个文本编辑器
  的聊天框不需要标题层级和表格，做了就得维护一个解析器。
- 代码块右上角一个「复制」和「插入到光标」两个小按钮，后者走草稿层。
- 面板不开时，`WM_AI` 照样收，结果留在模型里；打开就能看见，不丢。

### 7.2 行内补全（M4）

需要动 painter：`draw_line` 已经有二十来个参数，再加一个 `ghost: Option<&GhostText>`：

```rust
pub struct GhostText { pub line: usize, pub col: usize, pub text: String }
```

在最后一段、`fline == ghost.line` 时，用 `x_at(col)` 算出 x，推一条 `TextRun`，
颜色 `AiGhost`（默认取 `SubLan` 那一对，压到 45% 不透明度），**裁剪到行内**。
它不参与测量、不参与换行 —— 所以 `wrap` 数组在补全前后逐字节相同，这一条要写成断言。

触发与节流：停止输入 350 ms 后发；任何按键/选区变化/滚动/失焦/输入法组合立即取消；
最多显示 3 行 120 字符，超了就丢；大文件模式关。

### 7.3 行注记：审查结果

「审查当前文件」不吐一屏文字，而是把每条意见落到 `LineTips`：图标 + 一句话，悬停看
详情，`F8`/`Shift+F8` 在注记之间跳 —— 跳法就是 `cm_find_next` / `cm_find_prev` 那一套
（1401/1402），只是范围换成注记表。这样审查结果和编译错误、查找命中在界面上是同一种
东西。

### 7.4 主题键

新增六个键，全部**可缺省**，缺省时按既有颜色推（照 `caret_glow` 的先例，`theme.rs:258`）：

| 键 | 缺省推法 |
|---|---|
| `AiPanel` | `Default` 的背景 + `CallTip` 的前景 |
| `AiUser` | `Function` 的前景 |
| `AiBot` | `Default` 的前景 |
| `AiCode` | `CallTip` 那一对 |
| `AiGhost` | `SubLan` 前景，45% 不透明 |
| `AiDraft` | `Selection` 底色，压到 30% |

推得出就不必修 28 个主题文件；想定制的主题自己加键即可。主题对话框的「颜色」页是
12 列固定表，这些键不进表 —— 在文档里写明「AI 六个键只认 ini，不进对话框」。

## 9. 脚本接口

AI 是脚本的一个**原语**，不是脚本的替代品。`dg-script` 加四个函数：

```lua
App.ai.available()                     --> bool
App.ai.ask{ prompt=..., context="selection"|"file"|"none",
            on_done=function(ok, text) end }
App.ai.edit(instruction)               --> bool   走草稿层
App.ai.cancel()
```

- 回调不阻塞：走 `jobs::push_func` 那条队列，UI 线程在既有的 `run_queue` 里取。
- `context` 是白名单里的枚举，不接受任意字符串 —— 脚本不能偷偷把整个项目发出去。
- 这一个接口就能长出「翻译选中文本」「生成提交信息」「按模板写注释」这些包，而不必
  我们一条条加菜单。

## 10. 失败模式

失败必须说出来 —— 一个什么都不做也不说的命令，用户分不清它和坏掉的构建。

| 症状 | 原因 | 界面 |
|---|---|---|
| 401 / 403 | 密钥错、过期、额度没了 | 面板顶部红条 + 「重新填写密钥」按钮 |
| 429 | 限流 | 状态栏「被限流，12 s 后重试」；读 `Retry-After` 自动重试一次 |
| 连不上 | DNS / 代理 / 防火墙 | 「连不上 <host>：<系统错误原文>」 |
| 60 s 无数据 | 端点卡住 | 「60 秒没有响应」，取消键一直可点 |
| 流中断 | 连接被掐 | 保留已收到的部分，标「输出不完整」 |
| 空回复 | 拒答 / 内容过滤 | 「模型没有返回内容」+ `finish_reason` 原文 |
| 补丁不匹配 | 模型改错了上下文 | 「第 2 块没找到」+ 它以为的原文 |
| 大文件 | `doc.is_large()` | 命令灰掉，状态栏「大文件模式不支持 AI」 |
| 自签证书 | `ureq` 用 webpki 根证书 | 原文照抄，不假装成功；企业代理 v1 不特殊处理 |

## 11. 里程碑

### M1 骨架（能发、能收、能看见）

`dg-llm` 全部 + `ai.rs`（设置 + DPAPI）+ `aijob.rs` + 一个最小「提问」框（输入 → 流式
文本 → 复制）。不落编辑。

验收：`dg-llm` 单测覆盖 SSE 两种格式、错误映射、预算截断；手工跑通
OpenAI 兼容 / Anthropic / 本地 Ollama 三家；`--safe-mode` 下菜单全灰、抓包零请求。

### M2 选区改写 + 草稿层

`Ctrl+K` → 复核条 → 接受/撤销。`apply_replacements` + `apply_batch`。

验收：像素比（复核条三态：流中/待复核/已落定，`_pxdiff.py --crop 40`）；一次 `Ctrl+Z`
回退整批；多块补丁「有一块不中则全不中」；只读文档上命令是灰的。

### M3 对话面板

`PaneId::Ai`、chips、流式、`@` 引用、对话里的补丁落地。

验收：像素比（面板四态：空/流中/错误/完成）；流式期间输入不卡（连续敲字，帧间隔无
尖峰）；切标签再切回来，转录还在；面板关闭时结果不丢。

### M4 行内补全

painter 的 `GhostText` + FIM 请求 + `Tab` 接受 / `Ctrl+→` 接受一个词。

验收：像素比（一行 ghost / 超长截断 / 光标行末尾）；断言 `wrap` 数组补全前后逐字节
相同；连续输入 20 个字符只发 1 次请求（探针数线程）。

### M5 项目上下文 + 审查注记 + Lua 接口

关键词检索取上下文、`cm_ai_review` 落 `LineTips`、`App.ai.*` 四个函数。

验收：检索命中可解释（面板显示「检索：foo → 3 个文件 7 处」）；注记与 `F8` 跳转；
一个示例脚本包（`packages/ai-explain/`）能跑。

## 12. 风险与取舍

| 风险 | 影响 | 对策 |
|---|---|---|
| 密钥泄露 | 高 | DPAPI + ini 不落明文 + 文案不吹「安全存储」 |
| 用户没注意就外发了代码 | 高 | chips 明示、默认只发选区、`Context=` 白名单 |
| 模型乱改代码 | 高 | 草稿层 + 一步撤销 + 唯一匹配才落 + 任一不中全不中 |
| 流式刷新拖慢输入 | 中 | 30 ms 合并、只重排最后一条、转录上限 200 条 |
| 线程/连接泄漏 | 中 | 读超时 + 取消位 + 一文档一请求 |
| 端点协议变动 | 中 | 只认两种线格式；档案可手改；不内置任何厂商 SDK |
| 成本失控 | 中 | 行内补全默认关；面板显示 `usage`；`MaxOutput` 有上限 |
| 功能蔓延成一个 IDE | 中 | 非目标写在 §1.2：模型不执行操作，只产出文本与判断 |
