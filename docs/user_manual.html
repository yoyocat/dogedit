1 前言

欢迎使用 DogEdit——一个用 Rust 编写的原生文本编辑器。当前版本运行在 Windows；核心与窗口系统解耦，Linux 与 macOS 会在后续版本支持，届时复用同一套编辑能力与脚本接口。

1.1 DogEdit 是什么

DogEdit 是一款面向文本与代码编辑的桌面应用:当前接的是 Windows 原生外壳,外壳之下是平台无关的编辑核心(文档模型、自动换行布局、语法着色、渲染、LSP、脚本),后续可换接其它平台的外壳。它不依赖任何运行时环境,单个可执行文件连同随包数据文件即可运行。

主要能力一览:

  • 编辑核心:撤销/重做、多重选区与多光标、列模式、代码折叠、书签、行工具(排序/去重/对齐/注释等)、正则查找替换、在多个文件中查找替换。
  • 语法高亮:基于 tree-sitter 的语法解析,解析器以插件包形式随用随装(应用内下载、离线镜像、手工放置均支持)。
  • 大文件:超过 50 MB 的文件自动进入专用大文件模式,不整体载入内存,支持尾随日志等流式工作流。
  • 十六进制视图:以四种进制直接编辑字节,支持插入/覆写两种模式与原子保存。
  • 编码:BOM/UTF-16/UTF-8 自动识别、统计探测,内置 98 项代码页清单与收藏夹。
  • 语言服务(LSP):与 PATH 上的语言服务器对接,提供补全、跳转定义、悬停、签名帮助等。
  • 脚本:Lua 5.4 沙箱,支持脚本包、宏脚本、界面皮肤脚本,热重载。
  • 安全网:自动备份与版本历史、会话与热保存、崩溃恢复。
  • 外观:主题(颜色/几何/字体/形状四维定制)、深色模式、文档地图、覆盖式滚动条、DirectWrite/Direct2D 渲染。

本程序遵循 MIT 许可证,详见仓库中的 LICENSE 与 NOTICE。

2 快速上手

2.1 安装与目录

DogEdit 以便携版(绿色版)发行:解压 zip 到任意目录即可运行,不写注册表、不安装服务(只有两个可选的右键菜单项会写注册表,见 23.1 常规页)。解压后的顶层目录:

dogedit\
├─ dogedit.exe        主程序
├─ setting.ini        设置(空文件,首次运行起开始落盘)
├─ key.ini            快捷键(可直接编辑)
├─ template.ini       新建文件模板定义
├─ template\          模板内容文件
├─ lang\              界面语言表(zh-CN / en-US)
├─ themes\            配色主题
├─ packages\          随包脚本包(如示例包 LuaPaint)
└─ parsers\           解析器包(便携包默认不带,建议应用内下载)
setting.ini 必须存在 程序只在「读到的那个 setting.ini」上写回配置;文件不存在时所有设置写入都会放弃。便携包自带一个只含 [Setting] 的空文件,请不要删除它。若在开发目录里直接运行而没有这个文件,可手工新建一个。

除 exe 旁边的文件外,程序还会使用这些位置(详见 第 26 章):

位置用途
%LOCALAPPDATA%\DogEdit\backup自动备份与版本历史
%LOCALAPPDATA%\DogEdit\session会话快照与「热保存」内容
%LOCALAPPDATA%\DogEdit\packages用户安装的脚本包
%LOCALAPPDATA%\DogEdit\parsercache.json解析器下载列表的缓存
%APPDATA%\dogedit\parsers用户安装的解析器包
%APPDATA%\dogedit\iconthemes工具栏图标主题

2.2 启动与退出

  • 启动:双击 dogedit.exe。也可以把文件拖到 exe 上、或在命令行 dogedit.exe 文件名... 一次打开多个文件(命令行文件在会话恢复之后最后打开)。默认单实例:再启动一次只是把这次的文件交给已经开着的窗口、并把那个窗口带到前台,不会再开一个窗;要另起窗口请勾上「允许多个实例同时运行」或用「文件」→「新建实例」。
  • 新建实例:「文件」→「新建实例」(--new-instance)再启动一份程序,当前窗口的标签页一个都不动;新窗口不带文件参数,按自己的会话设置启动(默认是一个空白文档)。「分离到新实例」和改主题后的重启也带这个参数,所以单实例模式不会把它们转交回旧窗口。以 --safe-mode 启动时,新开的实例也是安全模式。
  • 打开文件的方式:「文件」→「打开」、拖放文件到窗口、目录树双击、「跳转」对话框(Ctrl+P)模糊搜索等。扩展名命中 [HEX] Ext(默认 dat;exe;bin;dll;hex;zip;rar)的文件会直接以十六进制视图打开。
  • 退出:「文件」→「退出」或 Alt+F4。退出时会先写下会话快照(打开的文件清单、光标、书签、以及「热保存」的未存内容),再逐个询问未保存的文档。
  • 关机退出:Windows 注销/关机同样会保存窗口位置与会话快照。

2.4 五分钟上手

  1. 打开一个代码文件。如果没装对应解析器,程序会弹「下载解析器」提示框——选中合适的解析器点「下载并安装」,新打开的文件立即生效着色。
  2. 查找:Ctrl+F 打开右上角查找条,按钮依次为:下一个 ▼、上一个 ▲、正则 .*、大小写 Aa、全字 ""、反向 ↺、查找全部 ≡、关闭 ✖。
  3. 换主题:「工具」→「设置」→「主题」打开「主题」对话框,可改颜色/几何/字体/形状;「查看」→「深色主题」切换深浅(重启生效)。
  4. 多光标:选中一个词按 Ctrl+D 逐个追加下一处,或 Alt+F3 选中所有匹配,直接同时编辑。
  5. 折叠:装了解析器的文件可语法折叠——Ctrl+K,Ctrl+1 折叠全部,Ctrl+K,Ctrl+J 展开。
  6. 快捷键:「工具」→「设置」→「快捷键」打开快捷键管理器,选中命令后捕获新组合点「分配」,即时生效并写回 key.ini。

3.1 新建

入口行为快捷键

模板可自行增删(选项 → 模板页),详见 23.6 模板页。

3.2 打开

  • 打开(Ctrl+O):系统文件对话框,支持多选。也可以从资源管理器把文件拖进窗口。
  • 打开文件夹内文件:先选目录,再列目录中的文件供挑选。
  • 恢复最后关闭的文件(Ctrl+Shift+T):按关闭顺序依次恢复。
  • 最近的文件:「文件」→「最近的文件」子菜单,默认记住 16 条(0–64 可调),条目里记着关闭时的行/列,点开后光标回到该处。「清除历史记录」清空列表。
  • 拖放:拖文件 = 逐个打开;拖文件夹到编辑区会弹菜单,可选「添加到快捷目录 / 插入文件路径 / 插入文件夹中的文件列表 / 打开文件夹内的文件」;拖文本 = 在落点插入(编辑器内拖动选区则为移动)。

  • 只读文件的修改处理方式由「选项 → 文件」页决定(蜂鸣 / 修改时提示 / 保存时提示 / 不提示)。
  • 关闭与退出时的保存询问:单个文档弹系统「是/否/取消」;批量关闭(关闭全部/其它/左侧/右侧、退出)弹五按钮对话框:「是 / 全是 / 否 / 全否 / 取消」。

3.4 重新读取与编码

  • 重新读取:放弃内存中的修改,从磁盘重读。
  • 指定编码加载:用选定的编码重新解释文件字节(不改文件)。
  • 转换编码:把内容转写到目标编码,保存时生效;支持 BOM 开关。详见 第 14 章。

3.5 文档信息

  • 重命名:就地重命名当前文件。
  • 复制路径 / 复制文件名:把当前文档的完整路径或文件名放入剪贴板。
  • 在文件管理器中打开:打开资源管理器并定位该文件。
  • 字符统计(「文档」菜单):统计字符、行、选区信息等;状态栏「选区信息」格点击同样打开。
  • 打印 / 打印预览 尚未提供:菜单行存在但当前版本不能打印。「选项 → 打印」页可以先配置边距与页眉页脚。

3.6 会话

「文件」→「会话」子菜单可以把当前打开的全部文档存成命名会话:

  • 保存到新会话…:命名并保存(文档清单、类型、编码、换行符、光标)。
  • 保存到当前会话:覆盖保存。
  • 清除会话菜单:删除已保存的会话名单。
  • 子菜单底部每个已保存会话一行,点击恢复。

会话文件(*.session)保存在 exe 目录。与「退出时自动恢复」是两回事:后者由「选项 → 会话」页控制,详见 第 22 章。

3.7 备份与历史

「文件」→「备份与历史…」打开备份历史对话框:按文件浏览历次备份、恢复、另存。自动备份的规则(间隔、版本数、保留天数、配额)见 第 22 章。

4 编辑文本

4.1 输入、插入与覆写

  • 默认为插入模式;按 Ins 或点状态栏「编辑模式」格在插入/覆写间切换。
  • 自动缩进:回车后新行继承上一行行首缩进(「文档」菜单可开关)。
  • 自动配对:输入左括号自动补右括号,引号(' / ")补成一对、光标停在中间;参与配对的是半角 () [] {} 和这两种引号,全角括号要由选项 → 编辑页的「中文括号(必须配对输入)」填进来才算;「按下Tab时跳出刚刚自动输入的配对字符」默认开启。
  • 光标列号默认从 0 开始计数(内部坐标就是 0 基);勾上「光标列号从1开始计数」只把状态栏「列」那一格往上挪 1,跳转框和命中测试不跟着变(选项 → 编辑页)。
  • 智能 Home:Home 移动到「子行头」——先跳过行首空白再回到真正行首;编辑器把折行产生的后半段视为「子行」,所以「移动到子行头/子行尾」在自动换行下行为符合直觉。
  • 光标位置历史:编辑器记住最近 10 个光标停留位置(按段落粒度),Ctrl+\/Ctrl+Shift+\ 在上一个/下一个位置之间往返;「查找」菜单 →「光标位置」另有编辑位置导航。
  • 交换字符(Ctrl+T):交换光标左右两侧的字符。
  • 在当前行之后/之前新建行:Ctrl+Enter / Shift+Enter,不移动光标位置语义,直接断行。

4.2 撤销与重做

  • Ctrl+Z 撤销、Ctrl+Y 重做;「已修改」状态按历史位置判定——撤销回保存点文档即恢复「干净」状态(标题的 * 消失)。
  • 撤销深度默认 1000 步;新编辑会清空重做栈。
  • 宏录制期间的所有编辑作为整体一步(复合撤销);宏暂停期间的编辑逐条入栈。
  • 全部替换的每一处替换是一条独立撤销记录,可以逐处回退。

6.2 查找选项与正则

四个开关作用于文档内查找:匹配大小写、全字匹配(词字符 = 字母数字与 _)、正则表达式、方向(向上)。行为细节:

  • 循环查找:向后找不到时回绕到文档开头继续(反之亦然);但「快速选择下一处」不回绕。
  • 跨行匹配:查找串本身含 \n/\r 时可跨行命中(如 a\nb);正则模式按行执行。
  • 大小写折叠按 Unicode 字符折叠,不只是 ASCII。
  • 正则引擎为 RE2 风格(Rust regex crate):不支持环视/后行断言,不支持反向引用出现在查找串中。替换串:文档内替换支持 $0–$9 分组引用(其余转义序列按字面写入);「在文件中查找和替换」的替换串另支持 \n 换行、\t 制表符与 $$ 表示字面 $(见其替换框的箭头菜单)。
「在文件中查找」正则菜单的预设记号 查找对话框的箭头菜单列出了常用记号(\n \t ^ $ . \b \w \s \d [] () | {n,m} * + ? 等)与 POSIX 类([:alpha:] [:digit:] 等),这些与引擎兼容。但其中 (?=exp) (?!exp) (?<=exp) (?<!exp)(环视)与 \c 汉字 \j 平假名 \J 片假名 \P CJK符号和标点 属于界面预设文案,当前引擎不支持——写成这样的模式不会产生任何匹配。

11 语法高亮、文件类型与解析器

DogEdit 的语法着色基于 tree-sitter;二进制里不内置任何语法,高亮与折叠能力全部来自 parsers\ 下的解析器插件包。没有解析器的文件仍可编辑,只是没有语法着色与语义折叠。

11.1 切换文件类型

「文档」→「切换文件类型…」,或点状态栏「语法着色类型」格。对话框列出全部可用的语法(首项「默认」= 摘掉语法),选「确定」把当前文档挂到该语法;「配置」按钮转到「语法着色」管理对话框。双击即确认。

文件类型的自动判定顺序:解析器包声明的 extensions(扩展名冲突时按包名字典序先到先得)→ filenames 精确文件名(如 Dockerfile)→ first_lines 首行嗅探(如 shebang)。几个常见扩展名即使没装包也有内置名字映射(rs→rust、py→python、json→json 等,但没有着色)。

11.2 解析器包

一个解析器包 = 一个目录:

parsers\
└─ lua\
   ├─ manifest.toml      包清单(必须)
   ├─ lua.dll            tree-sitter 语法 DLL(必须)
   └─ queries\
      ├─ highlights.scm  高亮查询(capture 名对应主题里的颜色键)
      └─ folds.scm       折叠查询

manifest.toml 的全部键:

键必填说明
name是包名,a-z 0-9 _ -,必须与目录名一致
display否显示名(状态栏/列表),缺省用 name
version否缺省 "0.0.0"
entry否DLL 导出符号名,缺省 tree_sitter_{name}(- 映射 _)
dll否DLL 文件名,缺省 {name}.dll,不允许路径分隔符
extensions否自动映射的扩展名(小写、无点、去重)
filenames否精确文件名匹配(如 Dockerfile),大小写不敏感
first_lines否首行前缀嗅探(如 #!/usr/bin/env lua),大小写敏感
abi否兼容的 tree-sitter ABI 区间(含端点),如 [13, 15]
max_file_bytes否超过此字节数的文件不附加本语法
[theme] 已废弃
manifest 里写 [theme] 段会直接报错:配色请写 queries/highlights.scm,capture 名对应的颜色在主题文件里(见 19.1)。

解析器搜索根(固定三处,不可配置):exe 目录 parsers\ → 工作目录 parsers\ → %APPDATA%\dogedit\parsers。停用名单写 setting.ini 的 [Syntax] Disabled=包名,包名。

11.3 解析器下载

「工具」→「设置」→「解析器下载…」打开管理对话框:

  • 筛选框实时过滤(名称/显示名/扩展名);刷新重新拉取列表(支持 ETag 缓存)。
  • 列表列:「名称 / 显示名 / 扩展名 / 版本 / 大小 / 状态」,状态有「未安装 / 已装 v* / 有更新 → v* / 已装(本地)」。
  • 下载/更新:下载 zip,经三道校验(sha256 对注册表声明、zip 内路径防穿越、解包体积上限),装到 %APPDATA%\dogedit\parsers,新打开的文件立即生效。
  • 卸载:仅对用户目录下的本地包可用。
  • 从文件安装…:选一个解析器包 zip 离线安装(不做 sha256 校验,信任本地文件)。
  • 双击行 = 下载/更新。

首开提醒:打开没有解析器的文件时自动弹「下载解析器」框,列出支持该类型的候选;「不再询问」把该扩展名记入 [Download] Dismissed。

离线安装(三选一):

  1. 「从文件安装…」直接装 zip。
  2. 本地镜像:setting.ini 写 [Download] Registry=D:\mirror,目录里放 registry.json 与 pkg\包名\版本.zip,此后全部零网络。
  3. 手工铺目录:把包目录整个拷进三处搜索根之一,再「重新扫描解析器」。

「查看」→「高级」(「文档」→「高级」)→「重新扫描解析器」把包清单与诊断写进输出窗格。

11.4 语法着色(包管理)

「工具」→「设置」→「语法着色…」打开「语法着色」对话框:

  • 摘要行:共 N 个解析器包,已启用 M 个。取消勾选的包不再被新打开的文件使用。
  • 带勾选框的列表,列「语言 / 显示名 / 扩展名 / 状态(未加载/已加载/加载失败)/ query」。
  • 「全选 / 全不选 / 在线获取...(转解析器下载)/ 确定 / 取消」;诊断行显示包级错误。
  • 确定后未勾选的包写入 [Syntax] Disabled。

11.5 注意事项

  • DLL 惰性加载、永不卸载:升级或更换语法 DLL 后需重启;停用包只是「不再被解析到」。
  • 只有 UTF-8 文档在后台线程解析;其它编码在窗口内同步解析。
  • highlights/folds 查询编译失败时退回按节点类型着色,错误在「重新扫描解析器」的报告里。
  • 大文件模式(第 15 章)不加载语法,改用行式词法器(仅对少数日志/数据扩展名)。
  • 修改已装包的折叠行为:编辑该包目录里的 queries\folds.scm。

12.1 词自动完成

  • 触发:键入 ≥2 个词字符后约 150ms 自动弹候选;「查看」→「显示自动完成候选词」手动触发(并入 LSP 候选)。「文档」→「自动完成」总开关。
  • 来源:当前文档单词(标记 -)+ LSP 补全(标记 L,仅手动触发时)。「选项 → 自动完成」页的来源清单(@ 代码片段 / 上下文单词 / 关键字 / 工程符号 / 文件名称)与「已选择」序号控制启用面。
  • 匹配方法:默认(前缀)/ 部分匹配(包含)/ 模糊匹配(子序列,不区分大小写),见「选项 → 自动完成」页。

14 编码、BOM 与换行符

14.1 编码自动识别

打开文件时按以下顺序判定编码:

  1. BOM 优先:UTF-8 / UTF-16LE / UTF-16BE / UTF-32 的字节序标记。
  2. 无 BOM 的 UTF-16:NUL 位模式启发。
  3. 严格 UTF-8 校验:能完整通过校验就按 UTF-8。
  4. 统计探测(chardetng):GBK、Shift-JIS、Windows-1252 等。

「选项 → 文件」页的「编码探测」开关控制 ANSI→UTF-8 的自动转换行为;「自动编码探测缓存大小(KB)」(性能页)控制探测缓冲。

14.2 「编码」对话框

「文档」→「转换编码」打开「编码」对话框,也可从状态栏「文件编码」格进入:

  • 左侧:收藏列表(默认 9 项:ANSI、UTF-8、UTF-16、UTF-16 BE、GB2312、Big5、Shift-JIS、Korean、Western European),可「添加/移除/上移/下移」,双击即确认。
  • 右侧:全部 98 项代码页——ANSI、UTF-8、UTF-8+BOM、UTF-16 LE/BE、GB2312/GBK/GB18030、Big5、Shift-JIS/EUC-JP/JIS 系、EUC-KR、各 iso-8859-x、Windows-125x、KOI8、Mac 系、DOS 系、EBCDIC、ISCII 等;代码页号 > 10 的显示 名称 [代码页]。
  • 确定时的选择即目标编码;收藏顺序写回 [Encoding] 节。
「指定编码加载」与「转换编码」的区别
「指定编码加载」([Setting] 之外无开关):按选定编码重新解释文件字节,用于打开乱码文件,不修改文件。
「转换编码」:把内容转写到目标编码,需要保存才落盘;UTF-16 页保存时带 BOM。

个别老代码页(UTF-7、EBCDIC、ISCII、DOS 中文、HZ 等)在内部转换层与系统 API 之间有差异,极少数页可能不可用——列表里能选,保存时以实际转换结果为准。

14.3 BOM 与新文件默认值

  • 状态栏「文件编码」格点击弹菜单:「指定编码加载 / 转换编码 / —— / 文件头(BOM)」;「文件头(BOM)」是勾选型开关,直接切换当前文档的 BOM。
  • 新文档默认格式(选项 → 文件页):换行符默认 CRLF (PC),编码默认 ANSI;默认编码可设 UTF-8 / UTF-8+BOM / UTF-16 LE/BE / GBK / Shift-JIS 等。
  • 保存时若来源带 BOM,会按 BOM 标志补回,不会悄悄丢失。

15 超大文件模式

文件达到 50 MB(内置阈值)时,打开动作自动路由到大文件后端:文件永不整体载入内存,按需读取,内存占用约为每行 4 字节的行索引加一个小文本缓存。

15.1 打开与索引

  • ≤8 MB 的内容区同步建全索引,秒开;更大的文件先建首屏 1 MB 与文末 2 MB(保证 Ctrl+End 立即可用),中间由后台线程补扫,完成后行号转为精确值。
  • 外部改写被监测到时会提示重载(旋转/截断检测)。

15.2 编辑与保存

  • 编辑在覆盖层上进行,总预算 256 MB;单次删除/替换超过 8M 字符会被拒绝。
  • 保存 = 原子替换 + 重开并恢复光标。
  • 自动备份对大文件不生效(见 22.1)。

见 6.6。两级树、双击跳转、新结果自动弹出。

21.2 Lua 脚本

DogEdit 内嵌 Lua 5.4 沙箱(mlua),脚本常驻进程、支持热重载(改文件即重跑,语法错误的版本不会顶掉正在工作的版本)。

安全边界

  • 只开放 coroutine/table/string/math/utf8 五个标准库——没有 os、io;唯一时钟是 App.now(),唯一 I/O 是 bridge 提供的。
  • 内存上限 64 MB;每个入口调用 2000 万条指令预算(死循环会被掐掉);定时器 ≤64 个;待办队列 ≤256。
  • 日志(print / App.log / 报错)落到 stderr(前缀 [lua] )与调试输出;App.alert 弹消息框(标题 DogEdit Lua)。
  • --safe-mode 启动则一条脚本都不跑;「脚本包」对话框停用的包写 [Scripts] Disabled。

25 命令行参考

参数行为
dogedit.exe [文件...]一次可给多个文件,按命令行顺序打开(会话恢复之后最后打开);命中 [HEX] Ext 的进十六进制视图。单实例模式下这些文件会被转交给已经开着的窗口
-g <目录> / --grep <目录>开窗后直接弹出「在文件中查找和替换」,文件夹预填成该目录。目录右键菜单的「用DogEdit在文件中查找」用的就是 -g
--new-instance一定另起一个进程,不把文件转交给旧窗口。「新建实例」「分离到新实例」和改主题后的重启内部都带这个参数
--selftest不开窗,跑编辑器核心自检,输出 selftest: OK / selftest: FAILED(退出码 0/1)
--ui-lint <脚本.lua>不开窗,离线体检一个绘制脚本(跑每个画法并报账)
--ui-doctor不开窗,把脚本包真装一遍并检查全部主题,输出诊断报告;错误退出码 1
--strict配合 --ui-doctor:提醒也按错误计
--packages不开窗,打印脚本包清单报告(id/版本/脚本/状态/来源/目录)
--safe-mode开窗的安全模式:脚本一条不跑、外部主题覆盖不生效、关闭两条热重载轮询;不写任何配置
--skin-debug开窗,绘制纯度检查(每个回调跑两遍比对;退出报总账)
--paint-stats开窗,绘制计时统计(环境变量 DOGEDIT_PAINT_STATS 等价)

启动流程要点:先判单实例([Setting] MulInst 为关且有同名互斥体时,把请求编成 WM_COPYDATA 交给旧窗口就退出)→ 读语言表 → Per-Monitor DPI 感知 → 装载脚本包(注册命令才有资格进菜单)→ 按上次退出记录摆窗 → 恢复状态栏次序、备份定时器、皮肤/主题热重载 → 备份恢复询问(如有)→ 会话恢复 → 打开命令行文件 → 处理 -g。其余 -- 参数静默忽略。

单实例:互斥体名字带 exe 路径的指纹,所以放在两个目录里的两份 DogEdit 不会互相抢文件;旧窗口靠窗口属性 DogEdit.Instance 认人。MulInst=Y、--new-instance、--safe-mode 三种情况都直接开新进程。转交的内容是一段带版本号的 UTF-8 请求,文件与 -g 都能带过去;旧窗口没应答时新进程会自己开窗,不会把用户挡在门外。窗口位置存 [Window] Rect/Zoomed。

28 常见问题

Q:打开代码文件没有语法高亮?

语法不随二进制分发。到「工具 → 设置 → 解析器下载」装对应解析器,或按 11.3 的三种离线方式安装;装完新打开的文件立即生效,已打开的文件可「文档 → 高级 → 重新加载着色」或重开。

Q:改了设置(主题、深色模式)为什么没生效?

深色主题与界面语言都需要重启;其余界面选项「应用」即生效。另外确认 setting.ini 存在——文件不存在时所有写盘都会放弃。

Q:配置文件在哪?为什么没有生成?

全部在 exe 旁边(setting.ini / key.ini / history.ini / *.session / themes\ / lang\ / template.ini),不在 %APPDATA%——这是便携式设计。setting.ini 缺失时程序不会替你创建(「选项」对话框确定时除外),手工新建一个只含 [Setting] 的文件即可。

Q:快捷键被占用/想改成别的键?

「工具 → 设置 → 快捷键」;冲突时程序会询问是否把旧绑定让出来。手工编辑 key.ini 也行(UTF-8、[Shortcut] 节、C/S/A+键=命令名、和弦用逗号)。

Q:误删/误改了文件内容,能找回吗?

两条路:①「文件 → 备份与历史」按版本恢复(需开启自动备份);②会话热保存(选项 → 会话页开启「记忆/恢复被修改的文件的内容」)保存退出前未落盘的内容。文件没保存就崩溃时,下次启动会自动弹恢复询问。

Q:大文件打开很慢/卡?

超过 50 MB 自动走大文件模式(秒开、不整体载入)。注意该模式下折叠、自动换行、LSP、自动完成、查找条全部替换不可用;替换用右键「替换结果导出」,日志场景用「尾随日志」。

Q:正则 (?=…) 为什么匹配不到东西?

正则引擎是 RE2 风格,不支持环视/后行断言(见 6.2 的警告框)。变通:用「查找全部」后手工筛选,或分两步查找。

Q:LSP 不工作?

当前只对 Rust 与 JSON 起 rust-analyzer,且要求它在 PATH 上;可用 [Lsp] Enable=N 关闭。补全用 Ctrl+Space 手动触发。

Q:如何离线安装解析器?

三种方式任选(11.3):从文件安装 zip、配置本地镜像目录、或把包目录拷进 parsers\ 搜索根。

Q:怎么把界面换成英文/其它语言?

「选项 → 语言」选 en-US(或放一个新 .lng),重启生效。语言表本身也是可编辑的文本文件(26.5)。

Q:如何为新文件配置默认编码/换行符?

「选项 → 文件」页:「格式」(CRLF/LF/CR)与「编码」(ANSI/UTF-8/UTF-8+BOM/UTF-16/GBK/Shift-JIS)。

Q:启动时想直接回到上次的工作现场?

「选项 → 会话」页勾选「启动时恢复上次退出前未关闭的文件」;需要连未保存内容一起恢复就再勾「热保存」。或者用「文件 → 会话」的命名会话手工管理。

[Theme]      颜色:Default/Selection/LineNumber/Found/Comment1/Comment2/

29.4 外部工具输出定位示例

让编译器输出可以双击跳转:动作模式选「捕获输出」,「高级」里勾「使用输出定位」,正则写 ^(.+)\((\d+),(\d+)\):,捕获下拉把「文件路径=捕获 1、行号=捕获 2、列号=捕获 3」;输出窗口的「下一个/上一个结果」即可按格式打开文件行列。
